# 1С: Проекты

> <img src="../resources/brand/cat-hi.png" alt="" width="26" align="left"> Проект переключается из статусной строки, не выходя из окна.

Проект это каталог с файлом `packagedef`: папка рабочей области или каталог внутри неё. В одном окне проектов бывает несколько, и у каждого свои профили запуска, окружения, база, `.1cpt`, `oscript_modules` и каталог сборки.

Панель **1С: Проекты** показывает проекты окна, находит проекты на диске и переключает между ними, в том числе без открытого проекта.

![Панель «1С: Проекты»](../walkthrough/images/step3.png)

## Формат

У строки проекта стоит **Конфигуратор**, **EDT**, **OneScript** или **1С**. Форматы исходного кода называются **1C:Конфигуратор** и **1C:EDT**. Расширение определяет формат само, пути к каталогам настраивать не нужно.

Профили запуска и настройки окружения в строке состояния есть у проекта любого формата. Автономный сервер есть у всех, кроме OneScript. Пока открыт файл вне проектов, они скрыты, а запущенный сервер виден всегда.

### Конфигуратор

Формат **1C:Конфигуратор**, в строке проекта подпись **Конфигуратор**. Это выгрузка конфигуратора. Панели, команды и тесты в остальных руководствах описаны для него.

### EDT

Формат **1C:EDT**, в строке проекта подпись **EDT**. Те же панели, команды и тесты, что у конфигуратора.

Команды над исходным кодом идут через консоль 1С:EDT, поэтому нужна установленная 1С:EDT. Без неё остаются тесты, сеансы и запуск Предприятия и Конфигуратора.

#### Команды над исходным кодом

Создание базы, загрузка и выгрузка, сборка и разборка работают у проекта EDT теми же командами дерева **[1С: Инструменты](tools.md)**. Разобранный `cf` ложится в проект конфигурации, расширения и внешние объекты в свои проекты. Внешний объект возвращается в тот проект, где лежит, не задевая соседей по проекту; объект без проекта получает новый рядом с остальными.

Выгрузка из базы кладёт в проект то, что есть в базе, и не убирает из него объекты, удалённые в базе.

**Конвертировать исходный код** в группах конфигурации и расширений переводит исходный код в другой формат силами EDT. Проекту расширения из выгрузки конфигуратора нужен базовый проект, поэтому сначала конвертируется конфигурация: её проект в каталоге сборки `cf-edt` и становится базовым.

У проекта EDT в плашке **Профиль запуска** есть строка `1С:EDT` с версией. Если EDT не найдена, строка скажет об этом, и команды над исходным кодом не пойдут.

#### Команды самой EDT

Группа **EDT** в дереве инструментов:

| Команда | Что делает |
| --- | --- |
| Импортировать в проект EDT | собирает проект из выгрузки конфигуратора вместе с расширениями |
| Выгрузить проект EDT в XML | обратное преобразование |
| Форматировать модули | приводит модули к стилю EDT |
| Сортировать объекты | порядок объектов конфигурации |
| Сведения о проекте | версия платформы, состав, зависимости |

Ещё две команды стоят в своих группах: **Запустить EDT** в группе **Запуск** открывает графический редактор с той же рабочей областью, **Проверка проекта EDT** в группе **Тестирование** проверяет проект средствами EDT. Замечания попадают в Problems с переходом в модуль, а замечания к самому объекту показываются на его описании.

#### Настройки

Настройки раздела **EDT**:

| Настройка | Зачем |
| --- | --- |
| `edt.path` | каталог установки, если расширение не нашло EDT само |
| `edt.version` | какая версия из нескольких установленных |
| `edt.workspace` | каталог рабочей области EDT |
| `edt.timeoutSeconds` | предел ожидания: импорт большой конфигурации идёт десятки минут |
| `edt.vmargs` | аргументы JVM, например `-Xmx8g` для больших конфигураций |

<img src="../resources/brand/bird-warn.png" alt="" width="28" align="left"> Рабочую область EDT занимает монопольно: пока идёт одна команда, вторая ждёт в очереди. Открытый графический редактор EDT занимает её так же: пока он открыт командой **Запустить EDT**, команды над исходным кодом не запускаются.

#### Метаданные

Панель метаданных, свойства объектов, диаграмма связей и правила поддержки работают на проекте EDT, как описано в [1С: Метаданные](metadata.md). Новые объекты, формы, расширения и внешние обработки заводятся из заготовок самой EDT, поэтому выглядят так же, как созданные в ней.

Расширение к проекту становится соседним проектом `<конфигурация>.<расширение>`. Внешняя обработка или отчёт живёт своим проектом.

### OneScript

В строке проекта подпись **OneScript**. Это библиотека или программа на файлах `.os`.

#### Публикация

**Опубликовать пакет** отправляет собранный файл `.ospx`. Канал и токен берутся из настроек окружения.

Там укажите `OPM_HUB_CHANNEL` со значением `stable` или `dev` и `GITHUB_OAUTH_TOKEN` с токеном. Если `OPM_HUB_CHANNEL` нет, канал определяется только в git-репозитории на ветке `master`.

#### Дерево метаданных

Панель **1С: Метаданные** показывает состав пакета. Классы, модули и программы читаются из `packagedef`, чтобы файл и его объявление оставались вместе: новый класс или модуль дописывается туда же, программа это `src/main.os`. Задачи это сценарии `.os` из каталога задач, по умолчанию `tasks`.

Профиль запуска у такого проекта один: [Профили запуска](launch-profiles.md#проект-onescript).

### Без исходного кода

Подпись **1С** у проекта без исходного кода 1С: `packagedef` зависит от vanessa-runner, vanessa-automation или add и не объявляет классы, модули или исполняемый файл. Так выглядит новый проект до первой выгрузки. Пока исходного кода нет, дерево метаданных пишет «Исходный код не найден».

## Раскладка проекта

Каталоги исходного кода настраивать не нужно: расширение само находит конфигурацию, её расширения, внешние обработки и отчёты в любом месте проекта и в обоих форматах.

Скрытые каталоги, каталоги сборки и пакетов расширение не просматривает, остальное лишнее исключает настройка `artifacts.exclude`.

## Проекты в окне

В проекте одна конфигурация, всё остальное в его каталоге относится к ней. Каталог внутри проекта со своим `packagedef` и своей конфигурацией это подпроект: на вкладке **Рабочая область** он стоит под родителем, а его расширения, кроме тестовых, есть и у родителя. Каталог с `packagedef` без своей конфигурации, например репозиторий расширения, внешней обработки или пакет OneScript, остаётся частью проекта.

Вторую конфигурацию без своего `packagedef` проект не берёт: она помечена предупреждением, и **Сделать отдельным проектом** кладёт ей `packagedef`. Папки рабочей области без `packagedef`, в которых нашлась конфигурация, собраны в группу **Не проекты**, проектом их делает **Инициализировать проект**.

Настройки путей, тестов, сервера и выбора расширений берутся из папки рабочей области, в которой лежит проект, поэтому у подпроекта они общие с родителем.

## Текущий проект

Команды, дерево метаданных, тесты, профиль и окружение работают с текущим проектом, а артефакты, пакеты и список дел показывают все проекты, текущий первым. На вкладке **Рабочая область** у строки проекта подписаны его именованный профиль и выбранное окружение. Текущий выбирают на вкладке **Рабочая область**, в списке из строки состояния или кнопкой **Выбрать проект** в заголовке деревьев команд и метаданных. Открытый редактор проект не переключает: команда над файлом или узлом дерева выполняется в его проекте.

Выбор запоминается для окна и в репозиторий не попадает. Пока ничего не выбрано, текущим считается проект из настройки `1c-platform-tools.project.default`, а без неё первый проект в корне папки рабочей области или первый найденный. В окне из нескольких папок эту настройку задают в файле `.code-workspace`.

## Поиск проектов

Вкладка **Все проекты** сканирует указанные папки и ищет каталоги с `packagedef`. Папки поиска задаются настройкой:

```json
{
  "1c-platform-tools.projects.path.baseFolders": [
    "~/projects",
    "D:/work/1c"
  ]
}
```

Если `baseFolders` пуст, вкладка ничего не найдёт, и добавить проект в избранное будет неоткуда. Лишние подпапки исключаются через `projects.ignorePatterns` (например `node_modules`, `out`), глубина сканирования — `projects.maxDepthRecursion`.

## Избранное и теги

- **Избранное** хранит выбранные проекты; отображение — списком или по тегам.
- Теги (например «Личное», «Работа») задаются настройкой `projects.tagList` и назначаются проектам из контекстного меню.

## Быстрое переключение

- Статусная строка показывает текущий проект, а в окне без проекта открытую папку. Клик открывает список: сначала проекты этого окна, выбор делает проект [текущим](#текущий-проект), затем Избранное и Все проекты для открытия.
- Команда **1С: Проекты → Открыть список** — из палитры или по `Ctrl+Alt+P` / `Cmd+Alt+P`.
- Поведение открытия (новое окно, подтверждение, фильтр по полному пути) настраивается ключами `1c-platform-tools.projects.*`.

## Синхронизация

`projects.path.storage` — папка для хранения `projects.json` (избранное и теги); укажите синхронизируемый каталог, чтобы переносить список между машинами. `projects.cacheBetweenSessions` ускоряет открытие панели за счёт кэша результатов сканирования.
