# 1С: Проекты

> <img src="../resources/brand/cat-hi.png" alt="" width="26" align="left"> Проект переключается из статусной строки, не выходя из окна.

Проект это каталог с файлом `packagedef`: папка рабочей области или каталог внутри неё. В одном окне проектов бывает несколько, и у каждого свои профили запуска, окружения, база, `.1cpt`, `oscript_modules` и каталог сборки.

Панель **1С: Проекты** показывает проекты окна, находит проекты на диске и переключает между ними, в том числе без открытого проекта.

![Панель «1С: Проекты»](../walkthrough/images/step6.png)

## Вид проекта

Проект с исходным кодом 1С подписан его форматом: **Конфигуратор** или **EDT**. Проект без исходного кода 1С это **1С**, если его `packagedef` зависит от vanessa-runner, vanessa-automation или add и не объявляет классы, модули или исполняемый файл: так выглядит новый проект до первой выгрузки. Остальные проекты это **OneScript**.

Методы описания пакета расширение читает из `packagedef` без его выполнения: имя, версию, `ВерсияСреды`, зависимости, классы, модули и исполняемые файлы, записанные строками. Вычисленное сценарием, например версия из модуля пакета, остаётся неизвестным.

Профиль запуска и окружение в строке состояния есть у проекта любого вида, автономный сервер — у всех, кроме OneScript. Пока открыт файл вне проектов, они скрыты, а запущенный сервер виден всегда. Пока исходного кода нет, дерево метаданных пишет «Исходный код не найден».

## Проект OneScript

Проекту OneScript платформа 1С не нужна. Дерево метаданных пишет «У проекта OneScript нет метаданных 1С» и md-sparrow не запускает, в артефактах только собранные пакеты `*.ospx`, в дереве **1С: Инструменты** только группы OneScript: зависимости, пакет, тесты, задачи и навыки. Проект с исходным кодом 1С остаётся проектом 1С и тогда, когда в нём есть скрипты OneScript; если его `packagedef` объявляет классы, модули или исполняемый файл, в дереве у него есть и группа **Пакет**.

Раскладка проекта OneScript та же, что у пакетов oscript-library и autumn-library:

- исходный код — обычно `src`: классы и модули без `lib.config` загрузчик библиотек находит в `src/Классы` и `src/Модули`, остальное пакет объявляет в `packagedef` (`ОпределяетКласс`, `ОпределяетМодуль`, `ИсполняемыйФайл`);
- тесты — каталог тестов проекта, другой задаёт `test.path.onescriptTests`;
- задачи `opm run` — каталог из `.Задачи(...)` в `packagedef`, без него `tasks`;
- зависимости — `oscript_modules`, туда их ставит **Установить зависимости**.

Новый проект OneScript создаёт **Создать проект** вариантом **Проект OneScript**: `packagedef` пакета с `ВерсияСреды` и инструментами тестов в `РазработкаЗависитОт` (oneunit, asserts, mutatos — в собранный пакет они не входят), каталоги `src/Классы`, `src/Модули`, `tests` с `oscript.cfg` для зависимостей из `oscript_modules` и `.gitignore`. **Инициализировать проект** в каталоге без исходного кода 1С спрашивает, какой проект создать.

## Раскладка проекта

Каталоги исходного кода настраивать не нужно: расширение само находит конфигурацию, её расширения, внешние обработки и отчёты в любом месте проекта и в обоих форматах.

Скрытые каталоги, каталоги сборки и пакетов расширение не просматривает, остальное лишнее исключает настройка `artifacts.exclude`.

## Проекты в окне

В проекте одна конфигурация, всё остальное в его каталоге относится к ней. Каталог внутри проекта со своим `packagedef` и своей конфигурацией это подпроект: на вкладке **Рабочая область** он стоит под родителем, а его расширения, кроме тестовых, есть и у родителя. Каталог с `packagedef` без своей конфигурации, например репозиторий расширения, внешней обработки или пакет OneScript, остаётся частью проекта.

Вторую конфигурацию без своего `packagedef` проект не берёт: она помечена предупреждением, и **Сделать отдельным проектом** кладёт ей `packagedef`. Папки рабочей области без `packagedef`, в которых нашлась конфигурация, собраны в группу **Не проекты**, проектом их делает **Инициализировать проект**.

Настройки путей, тестов, сервера и выбора расширений берутся из папки рабочей области, в которой лежит проект, поэтому у подпроекта они общие с родителем.

## Текущий проект

Команды, дерево метаданных, тесты, профиль запуска и окружение работают с текущим проектом, а артефакты и список дел показывают все проекты, текущий первым. На вкладке **Рабочая область** у строки проекта подписаны его именованный профиль и выбранное окружение. Текущий выбирают на вкладке **Рабочая область**, в списке из строки состояния или кнопкой **Выбрать проект** в заголовке деревьев команд и метаданных. Открытый редактор проект не переключает: команда над файлом или узлом дерева выполняется в его проекте.

Выбор запоминается для окна и в репозиторий не попадает. Пока ничего не выбрано, текущим считается проект из настройки `1c-platform-tools.project.default`, а без неё первый проект в корне папки рабочей области или первый найденный. В окне из нескольких папок эту настройку задают в файле `.code-workspace`.

## Поиск проектов

Вкладка **Все проекты** сканирует указанные папки и ищет каталоги с `packagedef`. Папки поиска задаются настройкой:

```json
{
  "1c-platform-tools.projects.path.baseFolders": [
    "~/projects",
    "D:/work/1c"
  ]
}
```

Если `baseFolders` пуст, вкладка ничего не найдёт, и добавить проект в избранное будет неоткуда. Лишние подпапки исключаются через `projects.ignorePatterns` (например `node_modules`, `out`), глубина сканирования — `projects.maxDepthRecursion`.

## Избранное и теги

- **Избранное** хранит выбранные проекты; отображение — списком или по тегам.
- Теги (например «Личное», «Работа») задаются настройкой `projects.tagList` и назначаются проектам из контекстного меню.

## Быстрое переключение

- Статусная строка показывает текущий проект, а в окне без проекта открытую папку. Клик открывает список: сначала проекты этого окна, выбор делает проект [текущим](#текущий-проект), затем Избранное и Все проекты для открытия.
- Команда **1С: Проекты → Открыть список** — из палитры или по `Ctrl+Alt+P` / `Cmd+Alt+P`.
- Поведение открытия (новое окно, подтверждение, фильтр по полному пути) настраивается ключами `1c-platform-tools.projects.*`.

## Синхронизация

`projects.path.storage` — папка для хранения `projects.json` (избранное и теги); укажите синхронизируемый каталог, чтобы переносить список между машинами. `projects.cacheBetweenSessions` ускоряет открытие панели за счёт кэша результатов сканирования.
