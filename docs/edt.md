# Формат EDT

> <img src="../resources/brand/cat.png" alt="" width="26" align="left"> Расширение находит исходники по маркерам, а не по настроенным путям.

Исходники конфигурации бывают в двух раскладках: выгрузка конфигуратора (`src/cf`, `src/cfe`) и проект 1С:EDT. Расширение работает с обеими и определяет формат само — по файлу `Configuration.xml` в каталоге конфигурации либо `src/Configuration/Configuration.mdo` в проекте EDT.

## Чем раскладки отличаются

| Что | Конфигуратор | EDT |
| --- | --- | --- |
| Конфигурация и расширения | подкаталоги настроенных путей | соседние проекты рабочей области |
| Исходники внутри | в корне каталога | в подкаталоге `src` |
| Описание объекта | `Catalogs/Валюты.xml` | `Catalogs/Валюты/Валюты.mdo` |
| Модуль объекта | `Catalogs/Валюты/Ext/ObjectModule.bsl` | `Catalogs/Валюты/ObjectModule.bsl` |
| Модуль формы | `.../Forms/Ф/Ext/Form/Module.bsl` | `.../Forms/Ф/Module.bsl` |
| Внешние обработки | каталог с корневым XML | проект с `src/ExternalDataProcessors` |
| Правила поддержки | `Ext/ParentConfigurations.bin` | `Configuration/Configuration.distr` |

## Конфигурация, с которой идёт работа

В рабочей области EDT конфигураций бывает несколько: сама конфигурация, её расширения и соседние проекты. Одна из них активна, и именно к ней относятся команды, панели и тесты.

Выбор — команда **1С: Проект → Выбрать конфигурацию проекта**; когда конфигураций больше одной, рядом с профилем запуска появляется элемент статусной строки с именем активной. Выбор хранится в рабочей области и не коммитится.

Расширения относятся к конфигурации по имени проекта, принятому в EDT: `ssl31._ДемоРасширение` рядом с `ssl31`. Расширение, не подошедшее ни к одной конфигурации, остаётся у активной — потерять его хуже, чем показать лишнее.

## Команды инструментов над проектом EDT

vanessa-runner читает выгрузку конфигуратора, а проект EDT в неё переводит сама EDT. Поэтому команда над исходниками EDT идёт в три шага, и все три видны в терминале задачами:

1. `1cedtcli export` проекта в каталог `build/edt-export/<проект>`;
2. команда раннера над этой выгрузкой;
3. `1cedtcli import` результата обратно в проект, если команда писала исходники.

Так работают создание базы из исходников, загрузка конфигурации и расширений, сборка `cf`, `cfe` и внешних обработок, выгрузка из базы в проект, разборка `cf`, `cfe` и `epf` в проект. Версия раннера роли не играет: он видит только выгрузку конфигуратора. Тесты, сеансы, запуск предприятия и конфигуратора с исходниками не связаны и идут как обычно.

Плашка **Профиль запуска** у проекта EDT показывает строку `1С:EDT` с версией: по ней видно, что исходники проходят через `1cedtcli`. Без установленной EDT команды над исходниками не выполнятся.

Выгрузка из базы кладёт в проект то, что есть в базе, а объекты, удалённые в базе, из проекта не убирает: так работает импорт самой EDT. Внешние обработки и отчёты собираются из своих проектов: у каждого в манифесте базовый проект конфигурации.

Конвертация форматов командами **Конвертировать исходники** остаётся за раннером `3.0.0-rc8` и новее; то же делают команды импорта и выгрузки группы **1С:EDT**.

## Команды самой EDT

Кроме vanessa-runner расширение умеет обращаться к 1С:EDT напрямую - через `1cedtcli` из её поставки. Так доступны действия, которых у раннера нет вовсе, и работают они независимо от его версии.

Группа **1С:EDT** в дереве инструментов:

| Команда | Что делает |
| --- | --- |
| Импортировать в проект EDT | собирает проект из выгрузки конфигуратора вместе с расширениями |
| Выгрузить проект EDT в XML | обратное преобразование |
| Проверить проект EDT | проверка средствами EDT; замечания попадают в Problems с переходом в модуль, а замечания к самому объекту показываются на его описании |
| Форматировать модули | приводит модули к стилю EDT |
| Сортировать объекты | порядок объектов конфигурации |
| Сведения о проекте | версия платформы, состав, зависимости |
| Открыть проект в EDT | графический редактор с той же рабочей областью |

Проект берётся у активной конфигурации. Расширения импортируются после конфигурации и с указанием базового проекта: без него EDT примет расширение за самостоятельную конфигурацию.

## Где расширение ищет EDT

EDT ставится своим установщиком с [releases.1c.ru](https://releases.1c.ru), поэтому расширение её не загружает, а находит: в Windows среди установок `1cedtstart`, в Linux в `/opt/1C/1CE/components`. Установка без `1cedtcli` пропускается - список версий у установщика переживает удаление самой EDT.

Найденная версия видна в сводке окружения (**Помощь → Скопировать сводку окружения**). Настройки раздела **1С:EDT**:

| Настройка | Зачем |
| --- | --- |
| `edt.path` | каталог установки, когда автопоиск не нашёл |
| `edt.version` | какая версия из нескольких установленных |
| `edt.workspace` | каталог рабочей области; по умолчанию в каталоге сборки |
| `edt.timeoutSeconds` | предел ожидания: импорт большой конфигурации идёт десятки минут |
| `edt.vmargs` | аргументы JVM, например `-Xmx8g` для больших конфигураций |

<img src="../resources/brand/bird-warn.png" alt="" width="28" align="left"> Рабочую область EDT занимает монопольно: команды выстраиваются в очередь, вторая ждёт первую. Поэтому рабочая область у проекта своя, а не общая временная.

## Метаданные проекта EDT

Дерево метаданных, палитра свойств, диаграмма связей, схемы компоновки, права ролей, состав планов обмена и командный интерфейс подсистем работают на проекте EDT так же, как на выгрузке конфигуратора. Свойства объекта и его реквизитов правятся точечно: меняется только тронутая строка файла. Реквизиты, табличные части, значения перечислений, измерения и ресурсы добавляются, переименовываются, копируются и удаляются; объект целиком тоже. Типы реквизитов и констант показываются и правятся в тех же подписях, что у выгрузки.

Новые объекты, формы, расширения и внешние обработки заводятся из заготовок, которые записала сама 1С:EDT: они лежат в сборке md-sparrow, у нового объекта свои идентификаторы, а ссылка в составе конфигурации встаёт на место по схеме. Расширение к проекту становится соседним проектом `<конфигурация>.<расширение>` с базовым проектом в манифесте; заимствованный объект получает свои идентификаторы и запись `Adopted`, как это делает EDT. Внешняя обработка или отчёт живёт своим проектом с базовым в манифесте. Команда **Создать новую конфигурацию** в панели метаданных спрашивает формат: для проекта EDT заготовкой служит пустая выгрузка, которую `1cedtcli` превращает в проект рядом с остальными.

Формы читаются и правятся: состав элементов, реквизиты, команды и палитра свойств элементов в подписях конфигуратора; свойство вида элемента ложится в его описание внутри файла формы. Правила поддержки поставщика EDT держит в `Configuration.distr`: дерево красит объекты и элементы по нему, режимы меняются там же, а запертый поставщиком объект панель не правит. Кнопка проверки у проекта EDT запускает **Проверить проект EDT**.

<img src="../resources/brand/bird-warn.png" alt="" width="28" align="left"> Панель метаданных работает с первой папкой рабочей области. В рабочей области из нескольких репозиториев откройте проект EDT отдельным окном.
