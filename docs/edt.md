# 1C:EDT

> <img src="../resources/brand/cat.png" alt="" width="26" align="left"> Проект 1C:EDT идёт наравне с 1C:Конфигуратор: те же панели, команды и тесты.

Команды над исходным кодом проекта EDT идут через её консоль, поэтому нужна установленная 1C:EDT. Без неё остаются тесты, сеансы и запуск Предприятия и Конфигуратора.

## Команды над исходным кодом

Создание базы, загрузка и выгрузка, сборка и разборка работают у проекта EDT теми же командами дерева **[1С: Инструменты](tools.md)**. Разобранный `cf` ложится в проект конфигурации, расширения и внешние объекты в свои проекты. Внешний объект возвращается в тот проект, где лежит, не задевая соседей по проекту; объект без проекта получает новый рядом с остальными.

Выгрузка из базы кладёт в проект то, что есть в базе, и не убирает из него объекты, удалённые в базе.

**Конвертировать исходный код** в группах конфигурации и расширений переводит исходный код в другой формат силами EDT. Проекту расширения из 1C:Конфигуратор нужен базовый проект, поэтому сначала конвертируется конфигурация: её проект в каталоге сборки `cf-edt` и становится базовым.

У проекта EDT в плашке **Профиль запуска** есть строка `1C:EDT` с версией. Если EDT не найдена, строка скажет об этом, и команды над исходным кодом не пойдут.

## Команды самой EDT

Группа **1C:EDT** в дереве инструментов:

| Команда | Что делает |
| --- | --- |
| Импортировать в проект 1C:EDT | собирает проект из 1C:Конфигуратор вместе с расширениями |
| Выгрузить проект 1C:EDT в XML | обратное преобразование |
| Форматировать модули | приводит модули к стилю EDT |
| Сортировать объекты | порядок объектов конфигурации |
| Сведения о проекте | версия платформы, состав, зависимости |

Ещё две команды стоят в своих группах: **Запустить EDT** в группе **Запуск** открывает графический редактор с той же рабочей областью, **Проверка проекта 1C:EDT** в группе **Тестирование** проверяет проект средствами EDT. Замечания попадают в Problems с переходом в модуль, а замечания к самому объекту показываются на его описании.

## Настройки

Настройки раздела **1C:EDT**:

| Настройка | Зачем |
| --- | --- |
| `edt.path` | каталог установки, если расширение не нашло EDT само |
| `edt.version` | какая версия из нескольких установленных |
| `edt.workspace` | каталог рабочей области EDT |
| `edt.timeoutSeconds` | предел ожидания: импорт большой конфигурации идёт десятки минут |
| `edt.vmargs` | аргументы JVM, например `-Xmx8g` для больших конфигураций |

<img src="../resources/brand/bird-warn.png" alt="" width="28" align="left"> Рабочую область EDT занимает монопольно: пока идёт одна команда, вторая ждёт в очереди. Открытый графический редактор EDT занимает её так же: пока он открыт командой **Запустить EDT**, команды над исходным кодом не запускаются.

## Метаданные проекта EDT

Панель метаданных, свойства объектов, диаграмма связей и правила поддержки работают на проекте EDT, как описано в [1С: Метаданные](metadata.md). Новые объекты, формы, расширения и внешние обработки заводятся из заготовок самой EDT, поэтому выглядят так же, как созданные в ней.

Расширение к проекту становится соседним проектом `<конфигурация>.<расширение>`. Внешняя обработка или отчёт живёт своим проектом.
