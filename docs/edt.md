# Формат EDT

> <img src="../resources/brand/cat.png" alt="" width="26" align="left"> Проект 1С:EDT идёт наравне с выгрузкой конфигуратора: те же панели, команды и тесты.

Исходный код конфигурации бывает выгрузкой конфигуратора или проектом 1С:EDT. Расширение работает с обеими раскладками, находит исходный код само и пути настраивать не просит.

Команды над исходным кодом проекта EDT идут через её консоль, поэтому нужна установленная 1С:EDT. Без неё остаются тесты, сеансы и запуск Предприятия и Конфигуратора. Где расширение ищет EDT, написано [ниже](#где-расширение-ищет-edt).

## Конфигурация, с которой идёт работа

В рабочей области EDT конфигураций бывает несколько: сама конфигурация, её расширения и соседние проекты. Одна из них активна, и именно к ней относятся команды, панели и тесты.

Выбор — команда **1С: Проект → Выбрать конфигурацию проекта**; когда конфигураций больше одной, рядом с профилем запуска появляется элемент статусной строки с именем активной. Выбор хранится в рабочей области и не коммитится.

Расширения относятся к конфигурации по имени проекта, принятому в EDT: `ssl31._ДемоРасширение` рядом с `ssl31`. Расширение, не подошедшее ни к одной конфигурации, остаётся у активной.

## Команды над исходным кодом

Создание базы, загрузка и выгрузка, сборка и разборка работают у проекта EDT теми же командами дерева **[1С: Инструменты](tools.md)**. Разобранный `cf` ложится в проект конфигурации, расширения и внешние объекты в свои проекты.

Выгрузка из базы кладёт в проект то, что есть в базе, и не убирает из него объекты, удалённые в базе.

У проекта EDT в плашке **Профиль запуска** есть строка `1С:EDT` с версией. Если EDT не найдена, строка скажет об этом, и команды над исходным кодом не пойдут.

## Команды самой EDT

Группа **EDT** в дереве инструментов:

| Команда | Что делает |
| --- | --- |
| Импортировать в проект EDT | собирает проект из выгрузки конфигуратора вместе с расширениями |
| Выгрузить проект EDT в XML | обратное преобразование |
| Форматировать модули | приводит модули к стилю EDT |
| Сортировать объекты | порядок объектов конфигурации |
| Сведения о проекте | версия платформы, состав, зависимости |

Ещё две команды стоят в своих группах: **Запустить EDT** в группе **Запуск** открывает графический редактор с той же рабочей областью, **Проверка проекта EDT** в группе **Тестирование** проверяет проект средствами EDT. Замечания попадают в Problems с переходом в модуль, а замечания к самому объекту показываются на его описании.

## Где расширение ищет EDT

EDT ставится своим установщиком с [releases.1c.ru](https://releases.1c.ru), поэтому расширение её не загружает, а находит: в Windows среди установок `1cedtstart`, в Linux в `/opt/1C/1CE/components`. Найденная версия видна в сводке окружения (**Помощь → Скопировать сводку окружения**).

Настройки раздела **EDT**:

| Настройка | Зачем |
| --- | --- |
| `edt.path` | каталог установки, когда автопоиск не нашёл |
| `edt.version` | какая версия из нескольких установленных |
| `edt.workspace` | каталог рабочей области EDT |
| `edt.timeoutSeconds` | предел ожидания: импорт большой конфигурации идёт десятки минут |
| `edt.vmargs` | аргументы JVM, например `-Xmx8g` для больших конфигураций |

<img src="../resources/brand/bird-warn.png" alt="" width="28" align="left"> Рабочую область EDT занимает монопольно: пока идёт одна команда, вторая ждёт в очереди. Открытый графический редактор EDT занимает её так же.

## Метаданные проекта EDT

Панель метаданных, свойства объектов, диаграмма связей и правила поддержки работают на проекте EDT, как описано в [1С: Метаданные](metadata.md). Новые объекты, формы, расширения и внешние обработки заводятся из заготовок самой EDT, поэтому выглядят так же, как созданные в ней.

Расширение к проекту становится соседним проектом `<конфигурация>.<расширение>`. Внешняя обработка или отчёт живёт своим проектом.

<img src="../resources/brand/bird-warn.png" alt="" width="28" align="left"> Панель метаданных работает с первой папкой рабочей области. В рабочей области из нескольких репозиториев откройте проект EDT отдельным окном.
