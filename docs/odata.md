# Данные через OData

> <img src="../resources/brand/cat-focus.png" alt="" width="26" align="left"> Спрашиваете агента о данных базы: он читает их через стандартный интерфейс OData.

Агент сам вызывает инструменты MCP `odata_query` (данные) и `odata_setup` (состав интерфейса). Вопросы пишутся обычным текстом.

## База проекта

1. Запустите [автономный сервер](autonomous-server.md) с отмеченным пунктом **OData**.
2. Включите нужные объекты в состав интерфейса: меню сервера → **Состав OData** или попросите агента. Объект вне состава отвечает ошибкой «не входит в состав».
3. Спрашивайте.

## Другая база: тестовая, прод

Нужны публикация со стандартным интерфейсом OData (IIS, Apache) и пользователь с ролью `УдаленныйДоступOData`. Для прода: пользователь только на чтение: запрет записи держится на его правах.

1. Создайте [профиль запуска](launch-profiles.md) с этим пользователем, например `prod`.
2. Назовите агенту адрес публикации и профиль:

   > По https://erp.company.local/erp с профилем prod: сколько заказов клиентов создано вчера?

Чтобы не повторять это в каждом вопросе, запишите адрес и профиль в правила проекта (`AGENTS.md`, `.cursor/rules`, `CLAUDE.md`).

Состав интерфейса прода настраивает администратор в самой базе.

## Примеры вопросов

- Какие справочники и документы доступны через OData?
- Покажи 10 последних заказов: номер, дата, сумма.
- Сколько номенклатуры помечено на удаление?
- Заполнен ли новый реквизит у заказов после доработки?
- Создай тестового контрагента «Проверка» и потом удали его.

## Что учесть

- Всё из ответа уходит в модель. Персональные данные запрашивайте, только если это можно.
- Без явного числа записей читаются первые 100 и общее число. Большая выборка нагружает сервер: уточняйте отбор и поля.
- Данные агент меняет только по вашей просьбе.
- Перечисление отдельно не читается: его значения видны в реквизитах объектов.

## Ошибки

| Ответ | Что делать |
|---|---|
| Публикация не отвечает | Проверить адрес и доступ к серверу из вашей сети |
| `401` | Проверить пользователя и пароль в профиле и роль `УдаленныйДоступOData` |
| `403` | Дать пользователю право на объект |
| Набор не входит в состав интерфейса | Включить объект в состав |
| Стандартный интерфейс не найден (404) | Включить OData в публикации |
