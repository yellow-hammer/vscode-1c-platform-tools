# Профили запуска

> <img src="../resources/brand/cat.png" alt="" width="26" align="left"> Профиль читают сами инструменты, расширение его не переписывает.

Профиль запуска — это режим, в котором расширение запускает всё в проекте: команды, тесты, отладку, публикацию сервера. Профиль один на проект и одинаков для проектов 1С, EDT и OneScript. У него две части, обе в корне проекта и обе необязательные:

- **настройки** — файл настроек vanessa-runner (`env.json` или `autumn-properties.json`): над какой базой и с какими параметрами идут команды. Его читает сам раннер;
- **окружение** — переменные среды из файлов `.env` (см. [ниже](#окружение-профиля)). Их получает каждый процесс, который запускает расширение.

Так одни и те же команды работают над разными базами — локальной, dev, демонстрационной, — а тесты идут с разными переменными, без правки самих команд.

## Формат зависит от версии vanessa-runner

Расширение само определяет установленную версию vanessa-runner и выбирает формат файла настроек:

| Версия vrunner | Базовый профиль | Именованный профиль |
| --- | --- | --- |
| 2.x | `env.json` | `env.<id>.json` (`env.dev.json` → профиль **dev**) |
| 3.x | `autumn-properties.json` | `autumn-properties.<id>.json` |

vanessa-runner 3 — это отдельный инструмент со своим форматом настроек (каскад `vrunner.<команда>.<опция>`), поэтому расширение **не конвертирует** `env.json` на лету. Профили обнаруживаются автоматически по именам файлов в корне проекта: базовый идёт первым, остальные — по алфавиту.

Перенос существующих настроек 2.x в формат 3.0 выполняется официальным инструментом из состава vanessa-runner.

У строки подключения к ИБ рядом с полем есть **«Выбрать базу…»** — список информационных баз платформы, тот же, что 1С показывает при запуске. Выбор подставляет строку в поле, поэтому вписать своё по-прежнему можно. Список читается из файла платформы (`ibases.v8i`), включая общие списки организации. Запустить базу из этого списка, не заходя в профиль, можно в панели [1С: Администрирование](admin.md).

### Личные настройки vanessa-runner 3

vanessa-runner 3 сам накладывает на `autumn-properties.json` ещё один файл: из переменной `VRUNNER_SETTINGS` или из ключа `vrunner.settings`. Так документация раннера предлагает держать личные значения разработчика в `autumn-properties.local.json` вне git. Расширение этот файл профилем не считает, но учитывает: плашка и тесты показывают значения так, как их увидит раннер. Переменную `VRUNNER_SETTINGS` можно задать и в окружении профиля — например, чтобы профиль `ci` локально шёл с файлом CI `tools/vrunner.json`.

## Окружение профиля

Переменные среды профиля лежат в файлах `.env` в корне проекта. Файлы накладываются друг на друга, следующий перекрывает предыдущий:

| Файл | Когда действует |
| --- | --- |
| `.env` | во всех профилях |
| `.env.local` | во всех профилях, личный |
| `.env.<id>` | в профиле `<id>` |
| `.env.<id>.local` | в профиле `<id>`, личный |

Профиль появляется и по одному файлу окружения: `.env.sqlite` даёт профиль **sqlite**, даже если своего файла настроек у него нет, — тогда команды vrunner идут с базовым файлом настроек. Образцы `.env.example`, `.env.sample`, `.env.template` и `.env.dist` профилями не считаются. Переменная профиля перекрывает унаследованную из окружения VS Code с тем же именем.

Формат — обычный dotenv, тот же, что у Docker Compose и библиотеки [dotenv](https://github.com/oscript-library/dotenv) для OneScript: `ИМЯ=значение`, комментарии `#`, кавычки, многострочные значения в кавычках, ссылки `${ИМЯ}` и `${ИМЯ:-запасное}`. Кириллица в именах допустима, поэтому так же задаются и настройки приложений на Осени (`mutatos_КаталогиТестов=tests`).

Шаблон `.gitignore` расширения не коммитит `.env`, `.env.local` и `.env.*.local`: пароли и личные адреса кладите туда. Общие файлы `.env.<id>` можно класть в репозиторий, и тогда в CI профиль поднимается теми же файлами.

Окружение получают команды vanessa-runner и opm, задачи oscript, тесты всех фреймворков, mutatos и 1cedtcli. В Docker переменные передаются в контейнер по имени (`-e ИМЯ`): значения в командную строку не попадают. В интерфейсе и в ответах агенту видны только имена переменных, без значений.

Переменные самого vanessa-runner сильнее файла настроек, но слабее временных параметров: базу, пользователя, пароль и версию платформы задают `VRUNNER_IBCONNECTION`, `VRUNNER_DBUSER`, `VRUNNER_DBPWD`, `VRUNNER_V8VERSION` у 3.x и `RUNNER_IBCONNECTION`, `RUNNER_DBUSER`, `RUNNER_DBPWD`, `RUNNER_V8VERSION` у 2.x. Поэтому профилю, который отличается только базой, хватает одного `.env.<id>`; плашка показывает базу с их учётом.

## Проект OneScript

У проекта OneScript нет vanessa-runner, поэтому профиль — это только окружение. Профиль **По умолчанию** есть всегда, остальные появляются по файлам `.env.<id>`. Например, для [entity](https://github.com/nixel2007/entity), где тесты переключают СУБД переменными среды:

```ini
# .env.sqlite
TESTRUNNER_RUN_SQLITE_TESTS=true
TESTRUNNER_RUN_POSTGRES_TESTS=false
```

```ini
# .env.postgres
TESTRUNNER_RUN_SQLITE_TESTS=false
TESTRUNNER_RUN_POSTGRES_TESTS=true
POSTGRES_HOST=localhost
POSTGRES_DATABASE=entity
```

Пароль `POSTGRES_PASSWORD` — в `.env.postgres.local`. **Создать профиль…** в проекте OneScript создаёт файл `.env.<id>`. Если проект на Осени, плашка показывает и `autumn-properties.json`: его приложение читает само.

## Панель «Профиль запуска»

Под панелью «Команды» находится плашка **Профиль запуска**. При первом открытии она свёрнута. В ней — что именно видят команды:

- **Профиль** — активный профиль (клик открывает выбор).
- **vanessa-runner: `<версия>`** — определённая версия и синтаксис (2.x/3.x); клик — определить версию заново (после переустановки раннера).
- **Файл настроек** — базовый файл схемы. Если файла нет, он не читается или записан в формате другой версии vanessa-runner, пункт подсвечен предупреждением, команды заблокированы, а подсказка говорит почему; клик создаёт файл или открывает его.
- **Окружение** — файлы `.env` профиля; в подсказке имена переменных. Клик открывает личный файл профиля, если он есть, иначе общий; файла нет — создаёт его.
- **ИБ** — строка подключения из файла настроек.
- **Временные параметры** — разовые переопределения (см. ниже).

У проекта OneScript в плашке только профиль, окружение и, если есть, `autumn-properties.json`.

## Статус-бар и выбор профиля

В статусной строке слева — элемент `$(rocket) <профиль>`, у проекта любого вида. Если базового файла настроек нет, элемент подсвечен предупреждением (команды заблокированы). Клик открывает меню **1С: Профиль запуска**:

- Список профилей — выбор активного (отмечен `$(check)`); справа файлы профиля.
- **Окружение профиля** — открыть файл окружения активного профиля.
- **Создать профиль…** — спрашивает идентификатор, создаёт `env.<id>.json` / `autumn-properties.<id>.json` (у проекта OneScript — `.env.<id>`) и делает его активным.
- **Открыть редактор профиля** — [форма-редактор](service-files.md) файла настроек.
- **Временные параметры** / **Сбросить параметры** — см. ниже.
- **Определить версию** — перечитать версию vanessa-runner.

Как раннер читает файл настроек из корня проекта сам, базовый профиль не требует `--settings` — расширение добавляет `--settings <файл>` только для **именованного** профиля со своим файлом настроек. Активный профиль у каждого проекта свой и в репозиторий не попадает.

Если удалить файлы активного профиля в открытом редакторе, проект сразу переключается на профиль «По умолчанию» — это видно в статусной строке. Если же выбранного профиля нет при открытии, например файл удалили при закрытом редакторе, команды и прогоны тестов не начинаются: иначе они пошли бы с чужими переменными. Сообщение предлагает выбрать профиль.

## Временные параметры

Поверх активного профиля можно задать разовые переопределения отдельными флагами — они применяются ко всем командам vrunner, не меняя файл профиля:

| Параметр | Флаг vrunner |
| --- | --- |
| Строка подключения к ИБ | `--ibconnection` (файловая `/F<путь>`, серверная `/S<сервер>\<имя_ИБ>`) |
| Пользователь ИБ | `--db-user` |
| Пароль ИБ | `--db-pwd` |
| Версия платформы | `--v8version` |
| Дополнительные параметры | `--additional` |

Заданы только непустые поля — остальное берётся из файла профиля. Когда переопределения активны (временные параметры или [env.local.json](#локальные-перекрытия-envlocaljson)), в статус-баре рядом с профилем появляется `*`. Временные параметры, как и выбор профиля, хранятся локально и не коммитятся.

## ИБ на каждую ветку: `${gitBranch}`

В значениях профиля работает переменная `${gitBranch}` — имя текущей ветки git, приведённое к безопасному имени каталога (`feature/RS-123` → `feature-RS-123`). Так у каждой ветки появляется своя информационная база:

```json
"--ibconnection": "/F./build/${gitBranch}"
```

Значение вычисляется в момент запуска команды — переключение ветки подхватывается сразу, без перезагрузки окна. Переменная поддерживается в опциях временных параметров (`--ibconnection`, `--db-user`, `--db-pwd`, `--v8version`, `--additional`) и работает также в самих временных параметрах и в [env.local.json](#локальные-перекрытия-envlocaljson).

<img src="../resources/brand/bird-warn.png" alt="" width="28" align="left"> Вне репозитория git подстановки не будет: значение уйдёт в команду как есть, с литеральным `${gitBranch}` в пути. Расширение однократно предупредит об этом.

## Локальные перекрытия: `env.local.json`

Файл `env.local.json` в корне проекта перекрывает активный профиль так же, как временные параметры, но задаётся программно — скриптами и git-хуками. Общий `env.json` остаётся нетронутым; файл под `.gitignore` (если строки нет — расширение предложит добавить).

```json
{
    "--ibconnection": "/F./build/${gitBranch}",
    "--db-user": "admin"
}
```

Приоритет: временные параметры > `env.local.json` > активный профиль. Применяются те же пять опций, что у временных параметров; прочие ключи пропускаются с пометкой в журнале. Файл читается на лету — правка git-хуком действует сразу.

<img src="../resources/brand/bird.png" alt="" width="28" align="left"> Когда перекрытия активны, у профиля в статус-баре появляется `*`, а в панели «Профиль запуска» — строка **Локальные перекрытия** (клик открывает файл).

## Секции команд при создании профиля

При создании базового профиля расширение предлагает отметить опциональные секции (базовые настройки подключения добавляются всегда):

- **vanessa** — сценарные тесты Vanessa Automation (BDD/feature);
- **xunit** — дымовые тесты xUnit;
- **yaxunit** — модульные тесты YAxUnit;
- **syntax-check** — синтаксический контроль конфигурации.

Секции добавляют в файл готовые блоки настроек в формате установленного vrunner (плоские секции в `env.json`, каскад `vrunner.test.*` / `vrunner.validate.*` в `autumn-properties.json`), которые ссылаются на файлы из каталога `tools/`.

## Редактор профиля

Файл настроек можно править как JSON вручную или через форму-редактор: пункт **Открыть редактор профиля** в меню профиля либо клик по строке «Файл настроек» на панели «Профиль запуска» открывает `env*.json` / `autumn-properties*.json` в удобной форме.

- Опции сгруппированы по смыслу (Подключение, Платформа, ibcmd и СУБД, ibsrv, EDT, Хранилище, Кластер, Vanessa, xUnit, синтаксический контроль, Запуск); нестандартные и редкие — в свёрнутой группе «Прочее».

- **Добавить параметр** и **Команда…** — выбор из известных опций через QuickPick с поиском по описанию; для 3.x параметры можно задавать пер-командно (каскад `vrunner.<команда>`).
- Правки пишутся в файл сразу, кнопки «Сохранить» нет. Форматирование и комментарии JSON остаются на месте, переключение между формой и текстом ничего не теряет.

## Где применяется активный профиль

Профиль — единая точка настройки: его учитывают **все** пути расширения.

- **Команды vanessa-runner и opm, задачи oscript** — `--settings` активного профиля подставляется централизованно; временные параметры и версия платформы берутся из профиля; процессы получают его окружение.
- **Панель тестирования** — все фреймворки, включая OneUnit, 1testrunner и 1bdd, запускаются под активным профилем. Именованный профиль подписан у корней дерева, а первая строка вывода прогона называет профиль, файлы настроек и окружения и имена переменных. Пути отчётов читаются из файла настроек профиля с учётом схемы.
- **Мутационное тестирование и 1cedtcli** — получают окружение профиля.
- **Автономный сервер (ibsrv)** — публикует ИБ активного профиля и его версию платформы; при смене профиля предлагает перезапуск, если работает на другой базе.
- **Отладка 1С** — строка подключения, учётные данные и версия платформы берутся из активного профиля.

## Настройки

- `1c-platform-tools.env.defaultProfile` — идентификатор профиля по умолчанию (имя `X` из `env.X.json` / `autumn-properties.X.json` / `.env.X`; пусто — базовый). В отличие от локального выбора, это значение можно закоммитить как общекомандный дефолт; локальный выбор его переопределяет.
