# Администрирование 1С

Панель **Администрирование 1С** в activity bar доступна всегда: проект 1С не нужен. Внутри два представления — **Информационные базы** и **Кластеры**.

Список баз запускает клиент 1С из записи платформы (`ibases.v8i`). Кластеры — консоль серверов через `rac`.

## Информационные базы

Представление показывает тот же список, что 1С при запуске: личный `ibases.v8i` и общие списки из `1cestart.cfg`.

### Как открыть базу

В строке базы две кнопки:

- **Предприятие**
- **Конфигуратор**

Клик по имени ничего не запускает. Та же команда есть в палитре: **1C: Информационные базы → Список информационных баз** — Enter открывает Предприятие, кнопки в строке выбора — Предприятие или Конфигуратор.

Запускает штатный `1cestart`: по имени записи (`/IBName`), а если такое имя в списке не одно — по строке подключения (`/F` или `/S`). Если в записи нет авторизации, 1С покажет своё окно входа.

### Откуда берётся список

| Источник | Где лежит |
| --- | --- |
| Личный список | Windows: `%APPDATA%\1C\1CEStart\ibases.v8i`; Linux и macOS: `~/.1C/1cestart/ibases.v8i` |
| Общие списки | Пути из `1cestart.cfg` (`CommonInfoBases`) |

Папки списка — как в файле (поле `Folder`). Список обновляется при открытии представления, по кнопке **Обновить** и при изменении файлов в каталоге платформы.

## Кластеры

Консоль администрирования кластера серверов 1С:Предприятие внутри VS Code. Работает через штатную утилиту платформы `rac`.

Из представления видно дерево: подключения → кластеры → информационные базы, рабочие серверы, менеджеры, процессы, сеансы, соединения и блокировки. Оттуда же выполняются административные действия, открывается таблица активности с метриками и карточка свойств базы.

### Что нужно для работы

1. **Установленная платформа 1С** на машине с VS Code — утилиты `1cestart` и `rac` входят в её поставку. `rac` работает по сети, поэтому для управления удалённым кластером локальной платформы достаточно.
2. **Запущенный сервер администрирования `ras`** на стороне кластера. Без него `rac` подключаться некуда: представление покажет ошибку соединения.
3. **Совпадение версий**: версия `rac` должна совпадать с версией сервера администрирования. Если на машине несколько версий платформы, нужную выбирают полем «Версия платформы» в параметрах подключения — у каждого сервера она своя.

Проверить, что утилита найдена и сервер отвечает, можно кнопкой **Проверить подключение** в форме подключения.

### Где ищутся rac и 1cestart

Путь определяется автоматически по тем же правилам, что и остальные бинарники платформы:

| ОС | Каталоги установки |
| --- | --- |
| Windows | `%PROGRAMFILES%\1cv8` |
| Linux, macOS | `/opt/1cv8/<архитектура>`, `/opt/1C/v8.3/<архитектура>` |

Первым проверяется каталог архитектуры текущей машины (`arm64`, `x86_64`, `i386`), затем `x86_64`. Внутри каталога версии бинарник ищется и в подкаталоге `bin/`, и напрямую — раскладки Windows, `.deb`-пакетов и `.run`-установщика различаются. Стартер `1cestart` живёт в `common` рядом с каталогами версий.

Если платформа установлена нестандартно, укажите каталог установки настройкой `1c-platform-tools.clusters.platformPath` — дальше расширение ищет утилиты само, как и для `ibsrv`.

### Подключения

Подключение описывает один сервер администрирования: адрес, порт и, при необходимости, администратора кластера.

Заводят и правят подключения в форме — отдельной вкладкой **Подключения к кластерам 1С**: слева список, справа поля. Открывается кнопкой **+** в заголовке представления, командой **1C: Кластеры → Создать подключение к кластеру** или пунктом **Свойства** в контекстном меню подключения.

- **Сервер администрирования (ras)** и **порт**: порт по умолчанию — **1545**.
- **Администратор кластера** и **пароль** — если в кластере заведены администраторы. Список кластеров и сведения о кластере платформа отдаёт без аутентификации, а базы, сеансы и соединения — только администратору кластера.
- **Администратор центрального сервера** и **пароль** — нужен единственному действию: правке свойств самого кластера. Кластер — объект уровня агента, и администратор кластера его параметры менять не вправе. Для дерева и остальных действий поле можно оставить пустым. Пустое поле пароля означает «оставить сохранённый»: правка соседнего поля доступ не стирает. Пароль убирается вместе с администратором.
- **Версия платформы** — какой `rac` вызывать. Поле предлагает версии, установленные на этой машине, но значение можно и вписать. Пусто — берётся наибольшая установленная.
- **Проверить подключение** — кнопка в форме: видно, найдена ли утилита, отвечает ли сервер и принимает ли он администратора. Если администратор задан, проверка дополнительно запрашивает базы первого кластера — список кластеров платформа отдаёт без аутентификации, и без такой проверки неверный пароль остался бы незамеченным до первого действия. Проверяются набранные значения, сохранять перед этим не нужно; итог остаётся точкой слева в списке: зелёная — всё сошлось, красная — нет.

Удаляют подключение крестиком в списке формы или пунктом **Удалить** в контекстном меню узла — без подтверждения: из списка исчезает запись, сам кластер и его базы не меняются. Правки применяются по кнопке **Сохранить**, до неё список не меняется.

Список подключений хранится в глобальном состоянии расширения и помечен как синхронизируемый, поэтому переезжает между машинами штатной **синхронизацией параметров VS Code** — включите Settings Sync, и подключения появятся на другой машине сами. Ни файла в проекте, ни отдельной настройки для этого не нужно.

**Пароли в списке не хранятся.** Пароль администратора кластера хранится в защищённом хранилище VS Code (SecretStorage), привязанном к подключению, и между машинами не синхронизируется — доступ к серверу не возят через облако. Пароль администратора информационной базы спрашивается только тогда, когда его требует платформа, и живёт в памяти до перезапуска окна — на диск он не записывается.

### Дерево кластера

Ветки загружаются по требованию: раскрытие узла — это обращение к серверу администрирования. Загруженное запоминается, поэтому повторная отрисовка новых вызовов не делает.

- **Информационные базы** — список баз кластера; внутри каждой свои **Сеансы**, **Соединения** и **Блокировки**, отобранные по этой базе.
- **Рабочие серверы** — центральный сервер идёт первым; внутри сервера — его **Рабочие процессы**.
- **Менеджеры кластера** — главный менеджер идёт первым, у каждого видны адрес и процесс операционной системы.
- **Администраторы** — учётные записи кластера: имя, описание и способ входа. Рядом с подключением есть такая же группа **Администраторы центрального сервера** — это отдельный список самого сервера.
- **Рабочие процессы** — адрес и порт в подписи, состояние и число соединений в описании; работающий процесс отмечен зелёным, остановленный — красным. Внутри процесса — его **Соединения**.
- **Сеансы** — номер и пользователь в подписи, приложение и компьютер в описании. Сеанс, ждущий блокировки СУБД или управляемой блокировки, подсвечен; спящий сеанс отмечен в описании.
- **Соединения** — номер, приложение, компьютер и время установки.
- **Блокировки** — что и когда заблокировано.

Рядом с названием группы показано количество объектов в ней. Если ветку прочитать не удалось, вместо списка появляется узел с причиной — дерево при этом остаётся открытым.

Кнопка **Обновить дерево кластеров** перечитывает всё, **Обновить** на узле — только его ветку. Значки в строке узла стоят в одном порядке по всей панели: сначала создание, затем правка и действие, обновление всегда последним справа.

#### Автообновление

Состояние кластера меняется само, поэтому дерево умеет обновляться периодически: кнопка в заголовке представления или настройки `clusters.autoRefresh.enabled` и `clusters.autoRefresh.intervalSeconds`. По умолчанию автообновление выключено, а включённое работает только когда представление видно — скрытое к серверу не обращается.

Состояние видно по самой кнопке: выключено — перечёркнутый значок и подпись **Включить автообновление дерева кластеров**, включено — обычный значок обновления и подпись **Выключить…**. Рядом с названием представления в этом случае появляется пометка «автообновление», чтобы периодические обращения к серверу не выглядели необъяснимыми.

### Таблица активности

Дерево показывает устройство кластера, но сравнить два десятка сеансов в нём неудобно. Команда **Сеансы и соединения таблицей** (на узле кластера или базы, значок в строке узла) открывает вкладку, где активность видна списком со столбцами.

- **Сеансы**: пользователь, приложение, компьютер, база, время начала и последней активности, память за вызов и всего, длительность текущего вызова и всех вызовов, число вызовов, процессорное время, объём и время обращений к СУБД, объём обмена с клиентом. Всё это платформа отдаёт одним вызовом — дополнительных обращений на строку нет.
- **Соединения**: номер, сеанс, приложение, компьютер, база, время установки и ожидание блокировки. Подробные метрики соединения лежат в его карточке — откройте подробности из дерева.

Что с таблицей можно делать:

- **сортировать** щелчком по заголовку — например, найти сеанс с наибольшим потреблением памяти или самым долгим вызовом;
- **искать** по строке поиска: отбор идёт по видимому тексту, поэтому ищутся и пользователь, и компьютер, и имя базы;
- **действовать по строке**: завершить сеанс, прервать его текущий серверный вызов, разорвать соединение — с теми же подтверждениями, что и в дереве;
- **выгружать**: кнопка **Копировать** кладёт в буфер обмена то, что видно на экране, с учётом поиска и сортировки. Разделитель «;», поэтому вставленное открывается Excel с русскими настройками.

Идентификаторы баз в таблице заменены их именами: администратор мыслит базами, а не GUID.

### Действия

#### Сеансы и соединения

- **Завершить** — из контекстного меню сеанса или значком на узле. В подтверждении можно выбрать «С сообщением…» — текст увидит пользователь в закрываемом сеансе.
- **Прервать текущий вызов** — мягче завершения: сеанс продолжит работу, оборвётся только затянувшийся серверный вызов (зависший отчёт или обработка).
- **Выключить** (на рабочем процессе) — процесс перестаёт принимать новые соединения и завершается, когда отпустит текущие; кластер поднимает замену.
- **Завершить все сеансы** — на узле базы; в подтверждении показано, сколько сеансов будет завершено. Чтобы пользователи не вернулись сразу же, сначала запретите начало сеансов.
- **Разорвать** — из контекстного меню соединения.

Необратимые действия по умолчанию подтверждаются; отключить подтверждение можно настройкой `clusters.confirmDestructiveActions` (завершение всех сеансов базы подтверждается всегда).

#### Блокировки информационной базы

- **Запретить / разрешить начало сеансов** (на узле базы) — при запрете спрашиваются сообщение для пользователей и код разрешения, позволяющий войти вопреки блокировке. Начало блокировки расширение проставляет текущим временем: в базе мог остаться интервал от прошлого раза, и с датой в прошлом запрет не сработал бы. Снятие блокировки сообщение и код не затирает.
- **Запретить / разрешить регламентные задания**.

Если платформа требует администратора информационной базы, расширение спросит имя и пароль и повторит операцию. Введённые данные запоминаются до перезапуска окна, чтобы не спрашивать их при каждом действии с той же базой.

#### Администраторы

Списки видны в дереве и правятся оттуда же:

- **Администраторы** под кластером — те, кого принимает `--cluster-user`: без них кластер открыт всем, кто дотянулся до `ras`.
- **Администраторы центрального сервера** под подключением — те, кого принимает `--agent-user`: они нужны правке самих кластеров.

Кнопка **+** на группе открывает карточку администратора, **Свойства** — ту же карточку для существующей записи, **Удалить** убирает её. В карточке задаются имя, описание и способы входа: паролем, средствами операционной системы (с указанием учётной записи ОС) или обоими сразу.

Создание и правка идут одной командой платформы: запись с существующим именем перезаписывается. Поэтому при правке имя не редактируется, а пароль задаётся заново — прочитать сохранённый платформа не даёт. Вход средствами операционной системы задают в консоли кластера: случай редкий, а полей ради него прибавилось бы вдвое.

Удаление последнего администратора снимает защиту целиком, поэтому подтверждение об этом прямо предупреждает.

#### Свойства объектов

У каждого объекта дерева одна кнопка — **Свойства**: она и показывает, и правит. Отдельных «подробностей» нет: администратору незачем помнить, у чего параметры, у чего сведения, а у чего правка.

| Объект | Что в карточке |
| --- | --- |
| Подключение | форма подключения к серверу администрирования |
| Кластер | параметры кластера, правятся администратором центрального сервера |
| Информационная база | блокировки, режим работы, профили безопасности |
| Рабочий сервер | диапазон портов, пределы памяти, ограничения на процесс, расписание перезапуска |
| Рабочий процесс, менеджер, сеанс, соединение | сведения и нагрузка, только для чтения: платформа менять их не даёт |
| Администратор | имя, описание и способы входа |

Карточки читаемые: объём показан в мегабайтах, длительность в секундах, метки времени в привычном порядке, идентификаторы приложений заменены названиями.

У каждого объекта своя вкладка: свойства двух соединений или сеансов можно открыть рядом и сравнить. Повторное открытие того же объекта переиспользует его вкладку, а не плодит копии.

#### Свойства кластера

**Свойства кластера** (контекстное меню кластера) открывают карточку параметров: имя, перезапуск рабочих процессов (период, порог памяти, время превышения, порог ошибок, завершение зависших процессов, снятие дампа), сеансы и отказоустойчивость (принудительное завершение, уровень отказоустойчивости, балансировка нагрузки, уровень безопасности), проверка связи и расписание перезапуска.

Читается карточка без аутентификации, а **сохранение требует администратора центрального сервера** — задайте его в подключении, иначе форма прямо скажет, чего не хватает.

Часть параметров платформа принимает молча, но не применяет: вызов завершается успешно, а значение остаётся прежним (так ведёт себя, например, период перезапуска на кластере без соответствующих условий). Карточка перечитывает объект после сохранения и сообщает, что именно не принято, — «Сохранено; платформа не приняла: …», чтобы возврат поля к прежнему значению не выглядел ошибкой расширения.

#### Свойства информационной базы

**Свойства информационной базы** (контекстное меню базы) открывают карточку — то же, что показывает консоль кластера, но редактируемое:

- **Размещение** — имя, СУБД, сервер и база данных. Только для чтения: размещение меняют вместе с самой базой, а не из консоли кластера.
- **Блокировка сеансов** — запрет начала сеансов, сообщение пользователю, код разрешения и интервал действия (`с` и `по`). Формат даты — `2026-08-18T22:00:00`; пустое значение означает «без ограничения».
- **Режим работы** — запрет регламентных заданий, выдача лицензий сервером, описание базы.
- **Профили безопасности** — профиль базы и профиль безопасного режима для внешнего кода.

Сохраняются **только изменённые поля**: вызов `infobase update` присваивает всё, что в нём перечислено, и отправка формы целиком затёрла бы настройку, которую в это же время поменяли в другой консоли. Пустое поле при этом осмысленно — так значение стирается.

Если платформа потребует администратора информационной базы, расширение спросит имя и пароль и повторит операцию.

## Журнал

Вызовы `rac` и запуск баз пишутся в общий журнал расширения — канал вывода **1C: Platform Tools**. Записи кластера помечены скоупом `[clusters]`, запуска баз — `[ibases]`. В строке rac видно команду, время выполнения и число полученных объектов, а при неудаче — сообщение утилиты. Открыть журнал можно кнопкой **Показать журнал** в сообщении об ошибке или выбрав канал в панели Output.

Своего канала у панели нет намеренно: отдельный канал в расширении заводится только под живой поток чужого долгоживущего процесса (так устроен автономный сервер с выводом `ibsrv`), а короткие вызовы «запрос-ответ» удобнее читать вместе с остальными событиями — с общим уровнем подробности и фильтром. Уровень переключается командой **Developer: Set Log Level…**: на уровне `Debug` в журнал добавляется строка о старте каждого вызова rac — она нужна, если вызов повис и итога не будет.

**Пароли в журнал не попадают** — значения опций `--*-pwd` заменяются звёздочками. Имя пользователя остаётся: без него не понять, чей доступ отклонён. Учтите, что сама утилита `rac` получает пароль аргументом командной строки, а значит он виден в списке процессов операционной системы — ввода пароля через поток у неё нет.

## Настройки

| Настройка | По умолчанию | Назначение |
| --- | --- | --- |
| `clusters.platformPath` | `""` | Каталог установки платформы 1С для поиска `rac` и `1cestart` |
| `clusters.timeoutSeconds` | `30` | Сколько ждать ответа `rac` |
| `clusters.autoRefresh.enabled` | `false` | Периодически обновлять дерево кластеров |
| `clusters.autoRefresh.intervalSeconds` | `30` | Интервал автообновления |
| `clusters.confirmDestructiveActions` | `true` | Подтверждать завершение сеанса и разрыв соединения |

Все ключи начинаются с `1c-platform-tools.`. Открыть раздел целиком — кнопка с шестерёнкой в заголовке представления «Кластеры» или команда **Настройки кластеров**.

## Если что-то не работает

| Симптом | Причина и что делать |
| --- | --- |
| «Не найден 1cestart» | Платформа установлена нестандартно — укажите `clusters.platformPath`. |
| «Каталог базы не найден» | В `ibases.v8i` указан путь, которого нет на диске. |
| «Утилита rac не найдена» | Платформа установлена нестандартно — укажите `clusters.platformPath`. В сообщении перечислены проверенные каталоги. |
| «Проверьте, что сервер администрирования (ras) запущен» | Не поднят `ras` либо неверны адрес и порт. Порт по умолчанию — 1545, у `ras` он задаётся при запуске. |
| «Укажите администратора кластера и пароль» | В кластере заданы администраторы: впишите имя и пароль в параметры подключения. |
| Несовпадение версий | Версия `rac` отличается от версии сервера — выберите нужную версию платформы в настройках или в подключении. |
| Вызовы обрываются по таймауту | Сервер недоступен или отвечает медленно: проверьте сеть и увеличьте `clusters.timeoutSeconds`. |

Подробности любой неудачи — в журнале: сообщение об ошибке предлагает открыть его кнопкой.
