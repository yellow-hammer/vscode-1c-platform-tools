# AI и MCP

Расширение помогает AI-агентам (Cursor, Claude, Copilot) работать с проектом 1С: агент узнаёт, какие команды вызывать, и выполняет их через файл-триггер или MCP.

![Навыки для AI и MCP](../walkthrough/images/step9.png)

## Навыки для агента

В дереве **Инструменты 1С** → раздел **Навыки для AI**:

- **Добавить навыки разработки 1С (cc-1c-skills)** — XML, формы, роли, СКД, метаданные; скачиваются с GitHub при каждом вызове.
- **Добавить навыки расширения (команды и MCP)** — инструкции по командам расширения и MCP по доменам.

При установке выбирается папка назначения: `.cursor/skills/`, `.github/skills/`, `.claude/skills/` или другая, которую использует агент.

## Файл-триггер

Агент может создать файл `.cursor/1c-platform-tools-run-command` с одной строкой — идентификатором команды:

```txt
1c-platform-tools.run.designer
```

Расширение выполнит команду и удалит файл.

## MCP

Для прямого вызова команд агентом используется расширение [mcp-1c-platform-tools](https://github.com/yellow-hammer/mcp-1c-platform-tools). Установите его и откройте проект 1С.

**VS Code** больше ничего не требует: MCP-сервер регистрируется сам.

**Cursor** не поддерживает провайдер MCP-серверов VS Code, поэтому сервер подключается через `.cursor/mcp.json` проекта. Файл создаёт команда **«Настроить MCP для Cursor»** в дереве **Инструменты 1С** → **Навыки для AI** (она же в палитре). Команда пишет актуальный путь к серверу и параметры IPC, включает канал связи и сохраняет другие серверы файла; после неё перезагрузите окно.

Канал связи с сервером включается настройкой `1c-platform-tools.ipc.enabled`: команда настройки делает это сама, а при запуске расширение MCP предлагает включить канал кнопкой. Порт и токен задаются настройками `1c-platform-tools.ipc.port` и `1c-platform-tools.ipc.token`; при ручной настройке те же значения передаются серверу через `ONEC_IPC_PORT` и `ONEC_IPC_TOKEN`.

### Как агент работает с командами

- **Результат вместо «команда запущена».** Инструменты MCP по умолчанию ждут завершения и возвращают `{ success, exitCode, stdout, stderr }`; прогоны тестов дополняют результат счётчиками из отчёта, поэтому упавшие тесты не выглядят успехом. Терминальный режим (`wait: false`) остаётся для случая, когда пользователь смотрит ход выполнения сам.
- **Окна не открываются.** Команда, вызванная агентом, никогда не показывает окна выбора: если данных не хватает, возвращается ошибка с подсказкой, какие параметры передать. Интерактивные мастера (поставка, установка версии, создание профиля) агенту недоступны — они выполняются пользователем.
- **Окружение запуска.** `env_status` показывает активный профиль, файл настроек и строку подключения; `env_selectProfile` переключает профиль по имени. Разовый прогон под другим файлом настроек задаётся параметром `settingsFile` — активный профиль при этом не меняется, а параметры вызова имеют приоритет над временными параметрами профиля.
- **Ошибки видны как ошибки.** Упавшие тесты, ошибки синтаксического контроля и ненулевой код возврата помечают ответ как неуспешный, поэтому агент не принимает провал за выполненную работу. Синтаксический контроль возвращает список ошибок с путём к файлу модуля, а длинный вывод процесса обрезается до хвоста: полный лог остаётся в панели расширения.

Полный список параметров и примеры фраз для агента — в документации MCP-сервера: [параметры инструментов](https://github.com/yellow-hammer/mcp-1c-platform-tools/blob/main/docs/tool-parameters.md), [что писать агенту](https://github.com/yellow-hammer/mcp-1c-platform-tools/blob/main/docs/examples.md).
