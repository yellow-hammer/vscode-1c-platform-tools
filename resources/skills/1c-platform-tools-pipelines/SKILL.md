# Пайплайны

| Задача | Command ID | MCP | wait: true |
|---|---|---|---|
| Запустить цепочку | `1c-platform-tools.pipelines.run` | `pipelines_run` | результат |

Параметр `pipeline` обязателен: id или название из `.1cpt/pipelines.json`. Без него команда цепочку за пользователя не выбирает и возвращает ошибку со списком доступных.

`profile` и `environment` — профиль и окружение на этот прогон вместо выбранных в редакторе: id или имя файла, у окружения пустая строка — «По умолчанию». Выбор пользователя не меняется. Передавай их, только если пользователь назвал профиль или окружение для прогона.

Шаги идут по связям. Упавший шаг без ветки error останавливает свою ветку. Шаг с подтверждением в агентном запуске завершается ошибкой. В ответе пошаговый отчёт.

В файле у цепочки и шага бывают свои `profile` и `environment`, они сильнее параметров прогона. Без поля у шага — как у цепочки, у цепочки — как выбрано в редакторе; `@editor` — как выбрано в редакторе, `environment: null` — «По умолчанию». Цепочка со ссылкой на профиль или окружение, которых нет в проекте, не запускается.

Редактор цепочек, добавление шаблонов и запуск с выбором профиля в MCP не публикуются: `1c-platform-tools.pipelines.openEditor`, `1c-platform-tools.pipelines.addTemplates`, `1c-platform-tools.pipelines.runWith`. Файл `.1cpt/pipelines.json` правь сам. То же для хуков: `1c-platform-tools.hooks.openEditor`, файл `.1cpt/hooks.json`.

## Примеры

- Запустить цепочку `load`: `pipelines_run` с `pipeline: "load"`.
